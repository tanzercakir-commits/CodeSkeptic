# Bounded resilience qualification

This optional Linux qualification target exercises repository parsers and
codecs in-process. It never analyzes mutated C/C++ source, launches a worker,
loads a fuzzed filesystem path or calls MCP tools. These are deterministic
mutation checks, not a coverage-guided libFuzzer campaign or a CWE accuracy
sample. No measured success is claimed by adding this harness.

Configure `CODESKEPTIC_BUILD_RESILIENCE=ON` explicitly to build
`codeskeptic_resilience` against the real `codeskeptic_core`. The default is OFF.
Use separate ASan+UBSan and UBSan-only build directories; never change the
normal build's instrumentation in place. Supply matching compile/link flags
at configure time (`-fsanitize=address,undefined` or `-fsanitize=undefined`,
`-fno-sanitize-recover=all`, `-fno-omit-frame-pointer`, `-O1`, `-g`). Keep the
cached compiler/dependencies and disconnected acquisition policy. Imported
LLVM/Clang libraries are not retroactively instrumented.

ASan cannot be a valid normal-worker profile with the production POSIX
address-space cap. Do not relax that cap to obtain a pass. ASan covers the
contract/sidecar, MCP envelope, worker-codec, input identity and disk-store
in-process slices. UBSan covers actual coordinator/resource/cache/checkpoint
integration with unchanged production limits. Normal full Linux, existing
stress profiles and required hosted Windows gates remain separate requirements.

## Frozen mutation recipes

The driver source is the versioned seed recipe. Seed 20260907 and exactly 4096
mutations per target are fixed by the supervisor, independent of observations.
All initial seeds and every strict prefix execute first. Xorshift64 chooses a
seed, byte and offset; operations cycle through replacement, insertion, deletion,
truncation and bounded repeated-byte append. Mutation buffers are at most64KiB.
The output records actual executions, seed recipe hash, positive/rejection branch
counts and separate deterministic boundary assertions. Same-build worker packets
are generated by the actual encoder, not stale wire-format copies.

- `contract`: clause/comment/sidecar grammar, valid/malformed strings and signed
  literal boundaries; inclusive 64-level nesting,16KiB clause,1024/4096 records,
  and1MiB whole-input pairs are checked independently of ordinary mutations.
  Parsing twice must preserve complete structural values. Ordinary comment
  errors may coexist with valid clauses; sidecar text entries are framing
  evidence only. Existing real loader tests preserve atomic model publication.
- `worker`: request and request-bound response codecs. Rejected decode preserves
  the complete caller sentinel; accepted decode must round-trip. Oversized packet
  refusal is checked. It does not treat every mutation as necessarily invalid.
- `identity`: input-witness and runtime-map decoding, transactional rejection
  and deterministic accepted output. No filesystem validation is performed on
  decoded observations. Existing real cache/store tests provide publication and
  stale-input evidence separately.

Each driver has a cooperative30-second mutation-loop budget and a hard60-second
external process-group deadline, with1GiB ASan hard RSS limit. Individual calls
are bounded by the real parser limits and the external deadline, not a claimed
per-input hard timer. Source/build version, executable hashes, actual elapsed
time, commands, discovery and full capped output are retained. The execution
environment must additionally impose process/CPU/memory limits (the local cached
profile uses2CPUs,6GiB,256PIDs and1GiB temporary space).

## Explicit gate

On a clean exact checkout and matching built artifacts:

```sh
bash scripts/test_resilience.sh --profile asan --build /absolute/asan-build \
  --revision FULL_SHA --out /absolute/new-evidence-directory
bash scripts/test_resilience.sh --profile ubsan --build /absolute/ubsan-build \
  --revision FULL_SHA --out /absolute/different-evidence-directory
python3 -B fuzz/test_runner.py
```

Output parents must exist; outputs cannot be inside the checkout or overwrite
previous evidence. Missing binaries, instrumentation, source identity, selected
tests, output records, actual process success or sanitizer failures reject the
gate. Zero tests/skips and incomplete output never become PASS. The supervisor
tests include real timeout, output overflow, nonzero/missing executables and
quiet-descendant cleanup, plus forged/missing success-record negatives.

Protected CMake/test-input changes require the active task's independent
old/new digest review and controlled inventory/catalog successor freeze before
qualification. Neither a build nor these scripts alone finalizes the FIFO task.
